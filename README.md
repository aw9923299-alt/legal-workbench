# 法务工作台

面向直播公司的企业级法务智能工作台。系统以飞书消息为入口，以 AI 管家为调度核心，把碎片化聊天、文件、@消息和通知聚合为可追溯、可协作、可结案的法务任务，并为后续专业 Agent 接入提供统一架构。

## 1. 核心痛点

1. **任务入口分散**：工作散落在群聊、私聊、@消息、附件、平台通知和临时口头沟通中，容易遗漏。
2. **消息不是任务**：聊天缺少明确标题、责任人、期限、材料和风险字段，人工整理成本高。
3. **同一事项反复出现**：不同群、不同时间段重复讨论，容易重复建单或丢失上下文。
4. **责任与等待不透明**：法务难以快速判断“现在该谁行动、在等谁、等什么、等了多久”。
5. **风险排序不足**：普通待办工具只看截止时间，无法同时考虑法律风险、业务影响和舆情后果。
6. **AI 不可追溯**：若不展示原始来源、判断依据和置信度，AI 结论无法用于专业工作。
7. **专业能力难扩展**：合同、广告、知识产权、诉讼等场景需要不同 Agent，但缺少统一调用、审批和回写规范。
8. **数据高度敏感**：聊天、合同、主播与争议信息不能默认全量读取，必须最小授权、分级访问和全量审计。

## 2. 产品目标与非目标

### 产品目标

- 自动发现经过授权的飞书信息中的潜在法务工作。
- 将非结构化消息转为结构化任务，并持续更新同一事项。
- 明确当前责任人、等待对象、下一步行动、期限、材料与风险。
- 在逾期、材料缺失、长期无进展和风险升级时主动提醒。
- 所有 AI 判断展示证据、置信度、来源和可撤销记录。
- 通过事项模板和统一 Agent 接口沉淀法务方法论。
- 支持从识别、确认、执行、协作、结案到复盘的完整闭环。

### 非目标

- 不替代法务人员作出最终法律判断或业务决策。
- 不默认读取全部飞书聊天或全部公司文件。
- 不在低置信度时自动创建正式任务。
- 不把系统设计成仅记录待办或仅展示统计图表的工具。
- 不允许 Agent 无审批地执行高风险外发、删除、归档或权限变更操作。

## 3. 核心用户流程

```text
飞书授权与同步
  ↓
消息清洗、线程上下文聚合、附件解析
  ↓
识别是否属于法务工作
  ├─ 高置信度明确交办 → 生成“待确认任务草稿”
  ├─ 边界不明确 → AI 收件箱
  ├─ 仅供知悉 → 信息记录/事项库候选
  └─ 无关消息 → 忽略并保留可纠正记录
  ↓
事项去重与历史任务关联
  ↓
人工确认：创建 / 关联 / 仅记录 / 忽略 / 修改字段
  ↓
任务分类、优先级、法律风险、业务影响评估
  ↓
执行：子任务、检查清单、材料、Agent 调用、协作
  ↓
持续读取新消息并更新进度
  ↓
提醒：截止、等待超时、材料缺失、风险升级
  ↓
结案：处理结果、沟通纪要、材料归档、结案总结
  ↓
将人工修正反馈给模型与规则层
```

### 关键判断规则

- **创建阈值**：高置信度也仅生成“待确认任务草稿”，不直接进入正式执行状态。
- **事项合并**：综合主体、合同、项目、参与人、关键词、时间窗口和消息引用关系计算关联分数。
- **状态约束**：每次状态变更必须同步更新下一步行动、行动责任人和下一次提醒。
- **人工反馈**：用户修改分类、风险、任务关联后，记录为训练样本或组织规则，不覆盖原始证据。

## 5. 主要页面说明

### 今日工作台

首页不以统计为核心，而是给出按“紧迫度 × 法律风险 × 业务影响 × 等待时长”排序的工作队列。顶部四项指标可以进入相应筛选视图；右侧 AI 管家引用具体任务、消息和期限给出建议。

### AI 收件箱

每条消息展示原文摘要、上下文、AI 判断、推荐分类、风险、优先级、置信度和判断依据。操作包括创建任务、关联已有任务、仅记录、修改提取、忽略。支持批量确认和批量关联。

### 任务中心

提供列表、看板、日历和时间线。列表用于高密度日常处理；看板用于状态流转；日历用于期限和履约节点；时间线用于查看跨群聊、跨日期的事项演进。

### 任务详情

主内容区承载处理工作区、上下文、文件、AI 记录、决策和变更；侧栏承载结构化字段、AI 透明度和 Agent 调用。所有 AI 内容都有视觉标识，不与人工确认信息混合。

### 法务事项库

每种专业事项保存默认字段、标准流程、风险检查、材料清单、SLA、审批节点和可调用 Agent。新任务确认类型后自动加载对应模板。

### Agent 中心

统一展示 Agent 能力、版本、权限、触发方式、成功率、执行成本和异常。写操作与高风险输出可配置人工审批，执行结果只能回写到声明的位置。

### 数据与权限

首次使用展示授权向导。群聊、私聊、文件分别授权；敏感群默认排除；用户可暂停同步、撤销授权、删除已同步数据并查看操作审计。

## 7. Agent 扩展架构

### 分层

```text
管家 Agent（Orchestrator）
  ├─ 识别与聚合层：消息识别、任务分类、实体解析、去重关联
  ├─ 专业分析层：合同、广告、知识产权、劳动、诉讼、检索
  ├─ 生产执行层：文书、材料整理、归档、纪要、提醒、报表
  └─ 治理层：权限校验、审批、审计、成本、失败重试、回滚
```

### 统一接口

```ts
AgentDefinition {
  agentId: string
  name: string
  version: string
  capability: string
  inputSchema: JSONSchema
  outputSchema: JSONSchema
  allowedDataScopes: DataScope[]
  triggerMode: manual | event | schedule | recommended
  executionStatus: enabled | paused | deprecated
  confidencePolicy: ConfidencePolicy
  riskLevel: low | medium | high
  approvalPolicy: ApprovalPolicy
  retryPolicy: RetryPolicy
  costPolicy: CostPolicy
  writeBackTargets: WriteBackTarget[]
}
```

### 执行流程

```text
触发请求
→ 权限预检
→ 任务快照与输入脱敏
→ Agent 执行
→ 输出结构校验
→ 置信度与风险门槛
→ 人工审批（如需要）
→ 结果回写
→ 审计日志
→ 失败重试或回滚
```

### 关键设计

- Agent 不直接访问页面状态，只通过服务层读取领域模型。
- 每次运行绑定 Agent 版本和任务快照，保证结果可复现。
- 高风险结论、外发文书、文件移动、删除和权限变更默认需要审批。
- 失败重试采用幂等键，避免重复创建任务、重复发送或重复归档。
- 成本按任务、事项类型、Agent 和时间维度统计。

## 8. 权限与数据安全

### 授权原则

- **默认不读取**：首次使用不自动同步任何会话。
- **最小范围**：群聊、私聊、文件分别授权。
- **私聊更严格**：仅同步明确授权线程、包含 @法务 的线程或用户手动转入的消息。
- **权限继承**：系统不得突破飞书原始文件权限。
- **实时可撤回**：暂停同步后不再新增读取；历史数据可按范围删除。

### 权限模型

```text
组织角色权限
  × 数据对象权限
  × 字段级权限
  × 操作权限
  × Agent 数据范围
  × 任务参与关系
```

### 必须审计的操作

- 授权范围变更、暂停和恢复同步。
- 查看、导出、删除敏感消息或文件。
- Agent 读取数据、生成结果、回写字段和外发内容。
- 任务合并、拆分、关闭和风险等级变更。
- 人工覆盖 AI 判断及撤销自动操作。

### 数据生命周期

- 原始消息、结构化任务和 Agent 运行记录分别设置保留期。
- 训练反馈使用脱敏后的结构化修正，不直接使用原始聊天全文。
- 任务关闭后按事项类型进入归档或定期删除。
- 删除任务不等于删除原始飞书消息；界面需说明数据边界。

## 11. 视觉设计规范

### 设计语言

- 专业、克制、稳定，优先支持高密度长时间办公。
- 主色为低饱和钢蓝；深色导航增强系统边界感。
- 高风险采用暗红和火山色小面积标识，不使用整屏红色。
- 圆角控制在 4–6px，减少消费级卡片感。
- 卡片主要用于功能边界，不把每个数据点都包成卡片。

### 色彩

| 用途 | 色值 |
|---|---|
| 主文本 | `#17243A` |
| 次文本 | `#657083` |
| 主品牌色 | `#315F8F` |
| 深色导航 | `#17243A` |
| 成功 | `#31735D` |
| 警告 | `#9C672C` |
| 高风险 | `#A84949` |
| 背景 | `#EDF1F5` |
| 边框 | `#D8DEE8` |

### AI / 人工 / 系统区分

- **AI 提取/建议**：钢蓝左边线、机器人图标、置信度与证据链接。
- **人工确认**：正常白底，显示确认人和确认时间。
- **系统记录**：灰色时间线或审计表，不与业务内容混排。

### 字体与密度

- 中文：PingFang SC / Microsoft YaHei。
- 正文 13–14px，表格 12–13px，页面标题 28–32px。
- 表格行高约 56–64px，保证信息密度和可点击性。
- 关键数字 24–28px，不采用超大营销数字。

### 交互

- `⌘/Ctrl + K`：全局搜索与命令面板。
- `C`：快速创建任务；`I`：进入收件箱；`G D`：今日工作台。
- 批量操作固定在列表顶部，危险操作二次确认。
- 自动操作提供撤销入口；撤销后记录审计日志。
- 表格列支持固定、拖拽排序、隐藏和保存个人视图。
