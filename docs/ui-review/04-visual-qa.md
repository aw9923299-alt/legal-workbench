# 今日工作台第一轮独立视觉验收

## 验收结论

- 发布建议：**不建议发布**。
- Blocker：0；High：3；Medium：3；Low：2。
- 三个规定视口均未出现页面级横向溢出；1440×900 的整体层级、配色和桌面密度基本成立，390×844 已切换为移动任务卡和 Drawer 导航。
- 但行动队列的数量与实际条目不一致，1024×768 会静默裁掉关键列，390×844 首屏看不到任何具体任务；这些问题会直接影响法务人员判断“有几件事要处理、下一步是什么、从哪里进入”，不满足发布门槛。

## Findings

### High

#### QA-H01｜行动队列数量与实际条目不一致

- 严重度：**high**
- 视口 / 路由：1440×900、1024×768、390×844；`/`
- 位置：`下一步工作队列` → `应立即处理` Tab
- 证据：Tab 徽标显示“应立即处理 4”，Playwright 在默认激活面板中实际计得 5 行桌面记录 / 5 张移动任务卡；三个视口均可复现。截图见 `artifacts/ui-review/before-1440.png`、`before-1024.png`、`before-390.png`。
- 实际表现：徽标口径是“紧急/高优先级”4 项，而列表口径包含所有“非低优先级”任务，因此额外展示一条中优先级任务。
- 期望：徽标数量、Tab 含义和列表成员必须由同一筛选口径派生，用户看到的数字应等于可处理条目数。
- 具体修改建议：只保留一份 `focusTasks` 派生结果，并同时用于 Badge 与 `TaskTable`；若产品需要纳入中优先级，则将 Tab 文案及摘要口径一并改为 5，避免分别维护计数和列表条件。

#### QA-H02｜1024 宽度静默裁掉“状态与操作”列，且无法横向滚动到达

- 严重度：**high**
- 视口 / 路由：1024×768；`/`
- 位置：行动队列桌面表格右侧
- 证据：表格固有宽度 1072px，实际容器宽度 914px；首行状态区域位于 `x=1043–1155`，完全在 1024px 视口外。表格及其祖先的 `overflow-x` 均为 `visible`，外层内容区再以 `overflow-x:hidden` 裁切，因此没有可用的横向滚动入口。截图 `artifacts/ui-review/before-1024.png` 中只露出“下一步行动”的一部分，“状态与操作”完全不可见。
- 实际表现：页面级溢出检测返回 false，但这是内容被裁切的结果；用户看不到状态标签和显式“进入事项中心”操作，下一步文字也被截断。
- 期望：1024 桌面/平板布局应在可视宽度内保留风险、期限、责任、下一步、状态和安全入口，不能用 `overflow:hidden` 隐藏关键内容。
- 具体修改建议：优先为 768–1100px 增加紧凑列方案（压缩来源与责任元数据、把状态和入口并入事项单元格或改用卡片）；若必须保留全表，则给 Ant Table 明确配置 `scroll.x` 并提供始终可发现的横向滚动，同时固定首列和操作列。修复后必须再次用坐标和真实滚动验证操作列可达。

#### QA-H03｜390 首屏被说明与摘要占满，看不到任何具体待办

- 严重度：**high**
- 视口 / 路由：390×844；`/`
- 位置：标题、数据边界提示、异常摘要与行动队列交界
- 证据：页面首屏高度 844px，行动队列标题约从 `y=789` 开始，第一张任务卡约从 `y=937` 开始；首屏没有出现任务标题、风险、期限或下一步。整页高度约 4124px。截图见 `artifacts/ui-review/before-390.png`。
- 实际表现：44px 主操作可见，但约 162px 的提示框和四个纵向指标单元占用大量垂直空间；用户必须滚动一屏以上才能看到第一项真正需要处理的工作。
- 期望：移动首屏仍应体现产品优先级，至少让行动队列和第一项任务的关键风险/期限进入或明显接近首屏，而静态说明与汇总保持低高度。
- 具体修改建议：移动端将四项异常摘要改为 2×2 紧凑布局；把数据边界说明收敛为一至两行摘要并允许展开查看详情；缩短标题区与模块间距。以“第一张任务卡关键标题和风险在 844px 内可见”为复验目标。

### Medium

#### QA-M01｜“今天 / 本周 / 全部”看似筛选，实际不改变队列

- 严重度：**medium**
- 视口 / 路由：1440×900、1024×768、390×844；`/`
- 位置：行动队列右上角 Segmented
- 证据：Playwright 点击“本周”后选中态正常变化，但前后五个任务标题及数量完全一致；无加载、禁用或“演示不可用”说明。
- 实际表现：控件提供明确可操作外观，却只更新自身选中状态，形成错误的时间范围反馈。
- 期望：范围切换应确定性过滤/排序同一份演示数据，或在能力未实现时移除控件、禁用并说明。
- 具体修改建议：让 `scope` 参与 `filteredTasks` 派生，并统一传给三个 Tab；若 mock 数据不足以可靠区分日期，本轮直接移除 Segmented，避免假交互。

#### QA-M02｜移动端多处触控目标小于 44px

- 严重度：**medium**
- 视口 / 路由：390×844；`/`
- 位置：顶栏、移动 Drawer、任务卡操作
- 证据：Playwright 实测顶栏菜单和通知按钮为 34×34px，Drawer 关闭按钮为 24×24px，导航项高 40px，任务卡“进入事项中心”高 32px；只有主操作达到 44px。
- 实际表现：关键导航和事项入口的点击热区偏小，单手触控时容易误触或点不中。
- 期望：移动端交互目标最小 44×44px，视觉图标可保持 16–20px，但点击热区不能缩小。
- 具体修改建议：统一为移动顶栏图标、Drawer 关闭按钮、菜单项和任务卡链接设置 `min-width/min-height: 44px`；链接可通过容器 padding 扩大热区而不增加文字视觉重量。

#### QA-M03｜12px 次要元数据对比度不足

- 严重度：**medium**
- 视口 / 路由：1440×900、1024×768、390×844；`/`
- 位置：指标提示、任务编号、风险理由/缺失材料等浅灰元数据
- 证据：使用的 `#8791a1` 在白底上的计算对比度约为 3.18:1；这些文本字号为 12px，低于普通文本 4.5:1 的常用可读性门槛。截图中 1024 和 390 的浅灰辅助信息最明显。
- 实际表现：长时间使用或低亮度屏幕下，任务来源和缺失材料等辅助证据不易扫读。
- 期望：12–14px 正常文本至少达到 4.5:1，并继续与正文保持层级差。
- 具体修改建议：复用已定义且对比度约 5.0:1 的 `#657083`，或建立不浅于该值的 secondary/meta token；不要仅用降低字号和降低对比度同时制造层级。

### Low

#### QA-L01｜桌面页面标题大于统一设计规格

- 严重度：**low**
- 视口 / 路由：1440×900、1024×768；`/`
- 位置：页面标题“今日工作台”
- 证据：Playwright 计算字号为 30px、行高 38px；统一设计规格为 24px。移动端已是 24px。
- 实际表现：标题略偏展示型，进一步挤压 1024 首屏的工作内容，但没有单独造成可用性失败。
- 期望：页面标题使用统一 24px 层级，依靠字重和间距建立上下文。
- 具体修改建议：桌面同样将 `.page-title-row h2` 收敛到 24px，并复查标题区与主操作的基线对齐。

#### QA-L02｜控制台持续输出 Ant Design 弃用警告

- 严重度：**low**
- 视口 / 路由：三个视口；`/`
- 位置：浏览器控制台
- 证据：每次刷新均记录 `[antd: Card] bordered is deprecated. Please use variant instead.`，以 console error 级别出现；未观察到 JavaScript `pageerror`。
- 实际表现：不影响当前渲染，但污染错误信号，会降低后续真实异常的可见度。
- 期望：默认页面刷新不产生组件 API 弃用错误。
- 具体修改建议：将首页 Card 的 `bordered={false}` 替换为当前 Ant Design 版本支持的 `variant` 写法，并确认视觉结果不变。

## 已通过项

- 1440×900、1024×768、390×844 的 `documentElement.scrollWidth === clientWidth`，无页面级横向溢出。
- 1440 桌面侧栏、1024 折叠侧栏、390 Drawer 三档响应式壳均能呈现。
- 390 Drawer 可打开并显示全部主导航与“处理待确认消息”；主操作可进入 AI 收件箱。
- 任务标题/“进入事项中心”可进入法务事项中心；未触发确认、审核、发送或其他业务状态写入。
- Tabs 可切换并更新任务集合；当前键盘焦点有可见 outline。
- 默认页未观察到 JavaScript page error 或失败请求导致的渲染中断。
- 未再出现“飞书同步正常”“AI 在线”“本地服务已连接”等未经证明的健康宣称；演示数据边界清楚。

## 网络与验证缺口

- 默认首页本身未出现影响渲染的失败请求。点击主操作进入 AI 收件箱时观察到 `/api/v1/auth/session` 返回 401，但演示目的页仍渲染；本轮无法据此证明真实鉴权链路可用，也未将其归入首页视觉缺陷。
- 浏览器会话首次启动曾出现一个不影响页面内容的 404 资源日志；未定位到影响渲染的业务资源。
- 本轮只对默认“今日工作台”做完整视觉验收；AI 收件箱和法务事项中心只做安全导航 smoke，不代表其页面已完成三视口视觉验收。
- 未触发会修改业务状态的确认、审核、发送、刷新数据等操作；未覆盖真实加载、空、失败、无权限、重试和禁用态。
- 未执行 typecheck、build 或后端测试；本报告只给出独立浏览器视觉结论，工程检查需由实现/集成验收统一记录。

## 复验门槛

修复后需在同一 URL、同一演示状态和三个规定视口重新截图并复测：行动队列数量、1024 关键列可达性、390 首屏、Segmented 实际过滤、移动触控热区、键盘焦点、控制台和失败网络请求。所有 blocker/high 清零且核心流程无影响可用性的 medium 后，方可建议发布。
