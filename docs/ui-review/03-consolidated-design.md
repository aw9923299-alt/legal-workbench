# 今日工作台统一设计方案

## 1. 目标与范围

目标页面是应用默认入口“今日工作台”。本轮将其收敛为“安静的法务控制台”：成熟、克制、可信，以待处理工作、风险、期限、责任和人工门禁为核心，不以 AI 对话框或装饰指标制造产品感。

本轮只调整前端展示、响应式和安全的页面内导航，不改变后端契约、正式业务状态、审核门禁或发送逻辑，不新增 UI 框架。

## 2. 分析结论与裁决

`product_ui_designer` 与 `ux_information_architect` 独立确认了以下共同问题：

1. `html/body/#root` 被锁定为最小 1024px，390×844 必然产生页面级横向溢出。
2. “本地服务已连接”“飞书同步正常”“AI 在线”等静态成功状态没有当前实现证据，损害可信度。
3. 同步提示、四项大指标和深色 AI 面板压过真正的行动队列。
4. 表格列过多，风险理由、缺失材料、等待对象和下一步行动反而难以扫描。
5. 首页缺少明确的数据边界；固定日期、统计和任务均来自演示数据。
6. 1024px 顶栏和侧栏没有有效收缩策略，390px 没有可用导航和任务呈现方式。

两份分析对数据策略存在取舍：UX 建议立即接入聚合 API，视觉设计建议在无真实状态时明确标注演示。考虑本轮“不改无关业务逻辑”和现有 Dashboard 缺少单一聚合契约，采用后者：

- 保留当前 mock 数据作为视觉演示快照；
- 在页面首屏明确标记“演示数据 / 非实时业务事实”；
- 移除或改写所有未经后端证明的“正常、在线、已连接”表达；
- 不把 mock 作为未来 API 失败时的静默兜底。

## 3. 唯一页面结构

### 3.1 应用壳

- 1440px：保留 228px 侧栏和紧凑顶栏。
- 1024px：侧栏自动折叠为 72px，缩短搜索区域，隐藏次要顶栏动作。
- 390px：隐藏固定侧栏，使用 Ant Design `Drawer` 提供移动导航；顶栏只保留菜单、页面身份和必要入口。
- 顶栏与侧栏状态使用“本地演示”或“状态待核验”，不得伪装实时健康结果。

### 3.2 页面上下文

首行展示：

- “今日法务工作台”；
- 说明“先处理硬期限、重大风险和等待人工决定的事项”；
- “演示数据”标签及快照日期；
- 唯一可用主操作“处理待确认消息”，进入现有消息研判页面。

移除无行为的同步按钮和首页新建任务主按钮。

### 3.3 数据边界提示

使用低高度中性提示条说明：当前首页是演示快照；真实同步、授权范围和服务健康以系统状态接口为准；专业 Agent、知识检索和真实外发不得表示为已上线。

### 3.4 异常摘要

保留 `MetricStrip` 文件与数据入口，视觉上改为紧凑异常摘要：

- 已逾期；
- 紧急/高优先级；
- 高/严重风险；
- 待人工确认。

数值从同一份演示数据派生；摘要负责快速扫描，不使用装饰箭头，也不伪装为尚未实现的筛选操作。

### 3.5 行动队列

行动队列提升为首个主表面，占据全部内容宽度。桌面表格固定优先展示：

1. 事项与来源；
2. 风险和优先级；
3. 截止时间；
4. 负责人和等待对象；
5. 下一步行动；
6. 当前状态与安全导航。

在任务摘要内补充一条风险理由、缺失材料数量和“AI 建议 / 人工建立”来源，不再让单独的 AI 置信度列占据主视觉。

390px 下不缩小桌面表格，改为任务列表卡。每项必须保留标题、风险、期限、负责人、等待/缺失材料、下一步和进入事项中心的操作。

### 3.6 辅助区

队列之后再展示：

- 即将发生的节点；
- 待确认消息摘要；
- AI 建议。

AI 区改为浅色、中性、低权重的“AI 建议（演示）”，明确“需人工确认”和依据范围；移除“在线”状态、自由聊天输入框和发送按钮。

本周统计降为页面底部的次级信息，不得抢占首屏。

## 4. 视觉语义

- 继续使用 Ant Design 与现有主题 token。
- 保留 `#315f8f` 主色、`#17243a` 正文、`#657083` 次要文字和 `#d8dee8` 边框。
- 红/橙只用于确定性风险、逾期和硬期限；蓝用于交互与系统信息；低饱和蓝紫用于 AI 建议；绿色仅用于经验证的成功结果。
- 页面标题 24px，区块标题 16px，正文 14px，元数据至少 12px；移动触控目标至少 44px。
- 使用 4/8/12/16/24 间距梯度和 6px 圆角；主工作面保留轻边框，辅助区减少阴影和卡片嵌套。
- 不使用渐变、玻璃拟态、霓虹、超大圆角、装饰图表或多套强调色。

## 5. 复用与预计文件范围

复用：

- Ant Design `Layout`、`Menu`、`Drawer`、`Alert`、`Tabs`、`Segmented`、`Table`、`List`、`Tag`、`Button`、`Tooltip`；
- 现有 `MetricStrip`、`TaskTable`、`AiAssistant`、`StatusTags`；
- `ConfigProvider` 主题 token、现有图标和页面壳。

预计修改：

- `apps/web/src/App.tsx`；
- `apps/web/src/pages/DashboardPage.tsx`；
- `apps/web/src/components/MetricStrip.tsx`；
- `apps/web/src/components/TaskTable.tsx`；
- `apps/web/src/components/AiAssistant.tsx`；
- `apps/web/src/styles/global.css`；
- 必要的 Playwright 响应式验收测试与配置。

不得修改 `mock.ts` 中的业务样例含义，不得扩展 `Task` 为正式领域模型，不得修改 API、后端或审核/发送规则。

## 6. 实施与测试门槛

实施前先增加 Playwright 行为测试，断言：

1. 390×844 默认页没有页面级横向溢出；
2. 三个规定视口都能看到页面标题和行动队列；
3. 390×844 能打开移动导航并看到主操作；
4. 首页不再显示未经证明的“飞书同步正常”“AI 在线”“本地服务已连接”。

先在当前实现上运行并确认测试因移动溢出或旧状态文案而失败，再实施并运行到通过。

工程检查：

- 执行仓库已有 typecheck 和 build；
- 执行新增 Playwright 测试；
- 若仓库没有 lint 或其他前端 test 脚本，明确记录“未配置”，不得声称通过。

## 7. 浏览器验收

同一默认页面、同一演示状态下验证：

- 1440×900；
- 1024×768；
- 390×844。

必须检查页面级横向溢出、移动导航、待确认主操作、任务入口、Tab/Segmented、焦点、控制台错误和影响渲染的网络失败。第一轮截图用于审查修复前证据，最终轮在相同条件下复验。

完成条件沿用项目 Skill：blocker 为零、high 为零、无影响核心流程的 medium、三个视口无页面级横向溢出、主操作可用、控制台无本次修改导致的严重错误、必要工程检查通过。
