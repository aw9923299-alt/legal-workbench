# 测试与质量要求

## 1. 测试层级

### 单元测试

重点覆盖：

- 任务状态迁移；
- 工作排序分数；
- 风险和优先级规则；
- 消息与任务关联候选；
- AI 置信度门槛；
- 字段来源和人工覆盖规则；
- 权限判断和 Agent 审批策略。

### 组件测试

重点覆盖：

- AI 收件箱单条与批量操作；
- 任务详情字段编辑；
- 等待状态表单的必填校验；
- 无权限、加载、空、失败和重试状态；
- AI/人工/系统内容的标识和来源跳转。

### 端到端测试

首条主路径：

```text
打开 AI 收件箱
→ 修改候选字段
→ 创建任务
→ 打开任务详情
→ 进入等待业务反馈
→ 填写等待对象与提醒时间
→ 恢复处理中
→ 完成并关闭任务
→ 查看审计时间线
```

## 2. 必测异常

- 同一飞书事件重复到达；
- 创建任务请求超时但服务端已成功；
- 原始消息被撤回；
- 文件权限被取消；
- Agent 输出结构不合法；
- Agent 执行超时或重复回写；
- 用户无权查看某字段；
- 任务在其他窗口已被更新；
- 长标题、长消息、空附件和大量标签；
- 网络断开后恢复。

## 3. 响应式检查

至少检查：

- 1920 × 1080；
- 1440 × 900；
- 1280 × 800；
- 窄屏退化布局，不要求移动端完整生产能力。

## 4. 提交前命令

```bash
npm run typecheck
npm run build
```

引入测试框架后，应追加：

```bash
npm run test
npm run test:e2e
```

## 5. 人工验收清单

- 页面标题、按钮和状态文本没有溢出；
- 重要操作有明确成功/失败反馈；
- 危险操作有确认与撤销路径；
- AI 内容带来源、置信度和标识；
- 无权限时不泄露字段内容；
- 深色模式下状态和风险仍可辨识；
- 键盘焦点可见，表单标签清晰；
- Mock 状态不会被误认为真实同步结果。
