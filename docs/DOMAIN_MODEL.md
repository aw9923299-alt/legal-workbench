# 领域模型与任务状态规则

## 1. 核心实体

### Task

法务工作闭环的主聚合。任务拥有当前状态、行动责任、风险、期限、来源、材料、决策、进度和结案结果。

### InboxCandidate

AI 从消息中识别出的候选事项。候选项与正式任务分离，只有人工确认或满足组织批准的自动化规则后才能转为正式任务。

### SourceReference

消息、文件或通知的不可变引用，记录原始 ID、会话、发送者、时间、上下文窗口、权限快照和内容摘要哈希。

### AgentDefinition / AgentRun

分别描述 Agent 的能力配置和一次可审计执行。运行记录必须绑定版本、输入快照、输出、审批、成本和回写结果。

### AuditEvent

记录人工、系统或 Agent 对领域对象实施的动作，保存变化前后值和来源。

## 2. AI 与人工字段

建议字段值使用带来源的结构，而不是只有一个裸值：

```ts
type SourcedValue<T> = {
  value: T;
  source: 'ai' | 'human' | 'system' | 'integration';
  status: 'proposed' | 'confirmed' | 'rejected';
  confidence?: number;
  evidenceRefs?: string[];
  generatedBy?: string;
  updatedBy: string;
  updatedAt: string;
};
```

生产实现可以采用字段级元数据表或事件溯源方案，不要求所有字段直接嵌套该结构，但必须保留等价信息。

## 3. 任务状态机

```text
待确认 → 待开始 → 处理中 ───────────────→ 已完成 → 已关闭
   │         │         ├→ 等待业务反馈 ─┤
   │         │         ├→ 等待外部反馈 ─┤
   │         │         ├→ 等待材料 ─────┤
   │         │         ├→ 待审批 ───────┤
   │         │         └→ 存在阻塞 ─────┤
   └─────────┴──────────────────────────→ 已取消
```

状态迁移不能只改状态文本，需同时校验以下字段：

| 目标状态 | 必填信息 |
|---|---|
| 待开始 | 负责人、下一步行动、计划时间 |
| 处理中 | 当前行动人、下一步行动 |
| 等待业务反馈 | 等待部门/人员、等待内容、催办时间 |
| 等待外部反馈 | 外部主体、等待内容、SLA 或升级规则 |
| 等待材料 | 材料清单、提供人、最晚时间 |
| 待审批 | 审批人、审批对象、审批截止时间 |
| 存在阻塞 | 阻塞原因、解除责任人、升级规则 |
| 已完成 | 处理结果、交付物、遗留风险 |
| 已关闭 | 结案总结、归档状态、关闭人 |
| 已取消 | 取消原因、决定人 |

## 4. 优先级计算

任务优先级、法律风险和业务影响必须分开存储。建议排序分数仅作为辅助：

```text
工作排序分数 = 截止紧迫度 + 法律风险权重 + 业务影响权重
             + 等待超时权重 + 明确升级信号 + 人工置顶
```

不得因为分数较低而隐藏严重法律风险。排序结果需展示主要构成理由。

## 5. 事项关联与去重

关联候选特征包括：

- 相同合同、项目、公司、主播、达人或案件；
- 相同发起人、参与人和来源群；
- 关键词及语义相似度；
- 消息引用、转发和线程关系；
- 时间窗口；
- 金额、日期、文件名和编号等强实体。

系统输出候选分数和理由。高相似度仍应允许用户选择“新建独立任务”。人工合并后需保留原任务 ID、消息来源和撤销路径。
