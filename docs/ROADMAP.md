# 开发路线图

本路线图用于 Codex 继续开发时确定优先级。每个阶段都应形成可运行、可测试、可演示的增量。

## P0：建立可持续开发基础

### P0.1 应用骨架

- 引入 React Router，为一级页面和 `/tasks/:taskId` 建立稳定 URL；
- 建立全局错误边界、通知与权限守卫；
- 将 Mock 数据访问集中到应用服务，不允许页面直接导入数据文件；
- 加入请求加载、错误、空数据和重试状态。

### P0.2 领域模型与状态机

- 扩展 Task、InboxCandidate、SourceReference、AuditEvent；
- 实现任务状态迁移校验；
- 实现等待对象、等待时长、下一步行动和提醒字段联动；
- 记录人工与 AI 字段来源。

### P0.3 AI 收件箱闭环

- 支持创建任务、关联已有任务、仅记录、忽略和修改提取结果；
- 支持批量确认、批量分类和批量关联；
- 记录每次人工修正；
- 防止重复处理和重复建单。

### P0.4 测试

- Vitest 覆盖状态机、排序、关联候选和权限判断；
- Testing Library 覆盖收件箱确认和任务状态编辑；
- Playwright 覆盖从候选消息到任务结案的主路径；
- CI 执行类型检查、构建和测试。

## P1：本地业务闭环与后端契约

- 建立 OpenAPI 契约和 Mock Server；
- 完成任务 CRUD、时间线、材料清单、提醒和审计接口；
- 实现事项库模板配置；
- 实现 Agent 定义、运行、审批、失败和回写界面；
- 实现全局搜索和命令面板；
- 实现保存筛选视图、列表列配置和批量操作。

## P2：飞书受控接入

- OAuth 和授权状态；
- 群聊白名单/黑名单；
- 私聊读取规则；
- 增量消息同步与幂等处理；
- 上下文窗口和文件元数据；
- 消息编辑、撤回、权限变化和同步暂停；
- 同步监控与告警。

先在测试租户和脱敏数据中验证，不能直接以生产全量会话试运行。

## P3：AI 识别与事项关联

- 法务相关性判断；
- 结构化字段抽取；
- 任务去重和历史事项关联；
- 风险、优先级和材料建议；
- AI 依据、置信度和模型版本展示；
- 误判反馈与规则管理；
- 离线评测集和回归评测。

## P4：专业 Agent 平台

- Agent 注册和版本管理；
- 权限范围、触发条件和审批策略；
- 合同审查、广告合规、知识产权、证据整理等首批 Agent；
- 执行沙箱、失败重试、取消和幂等；
- 成本、成功率和质量反馈；
- 结果回写与撤销。

## P5：生产治理

- 组织、角色、任务参与关系和字段级权限；
- 数据保留、删除、导出和法律留置；
- 敏感信息脱敏；
- 提示注入与恶意文件防护；
- 完整审计、监控、告警和应急开关；
- 性能、可访问性、灾备和安全测试。

## 当前首个建议开发任务

**标题：实现 AI 收件箱到任务创建的本地闭环**

验收条件：

1. 用户可以编辑 AI 建议字段；
2. 用户可以创建新任务或关联已有任务；
3. 处理后候选项不再出现在待确认列表；
4. 新任务显示来源消息、人工确认人和时间；
5. 重复点击不会重复创建；
6. 刷新页面后状态仍可通过 Mock API 或本地存储恢复；
7. 有单元测试、组件测试和一条端到端测试。
